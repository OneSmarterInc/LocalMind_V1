# Changes, 3 September 2026

## Publishing now reaches students immediately

Student visibility used to require three separate steps: publish the book, open each module, publish the quiz or assignment. Modules default to locked, so a quiz published on a locked module was invisible to students with no warning. Now:

- Publishing a book opens every module that has source text. Faculty can still lock modules or chapters afterwards; an unpublish/re-publish cycle keeps those locks.
- Publishing a quiz or assignment opens its module if it is locked (or every module of its chapter, when none is open).
- Each opening writes one `module.opened_on_publish` audit row carrying the reason and the module ids.
- The faculty screens say so next to the Publish buttons.

Backend: `learning/services.py` (`open_modules_for_publish`, `open_target_modules`), wired into `documents.services.publish`, `assessments.services.set_status` and `assignments.services.set_status`. Tests updated in `documents`, `assessments`, `assignments` and `scripts/system_test.py`.

## Parsing and outline

- Headings that precede the first chapter-level heading (a preface written as H2 before Chapter 1) are no longer dropped with their text; they become chapters.
- A chapter with no sub-headings becomes one module of itself, so a flat document can be published.
- A chapter whose own introduction (text before its first sub-heading) is substantial gets a "Chapter: Overview" module carrying that text; previously it was invisible to students.
- The inline heading repair (`para. ## Heading`) now requires the prefix to end like a sentence and the heading to start with a capital or digit, so `# comment` lines in code listings are not split into bogus sections.
- Section `end_page` no longer drifts onto the next page because of the blank lines that follow a page break.
- DOCX parsing reads inside content controls (`w:sdt`, used by cover pages and templates) and skips the generated table of contents.
- PDF parsing survives a machine without Docling or its model files: PDFs with a text layer are parsed from the text layer with heading inference; scanned PDFs get a precise error naming the missing OCR engine.

## Web client

- Ask-a-doubt: the chat area is now height-bounded with a visible, persistent scrollbar, so the input bar no longer scrolls off the page as the conversation grows; the newest conversation on the module is restored when the tab is reopened, and the view follows new messages.
- Confirmation dialogs (unpublish/archive on the book page, "submit with blank answers?" in the quiz) hung forever on web because React Native Web does not implement `Alert.alert` buttons. A cross-platform `confirmAsync` fixes both.
- Timed quizzes auto-submit when the clock reaches zero instead of leaving a dead attempt on screen.
- Browsers have no pull-to-refresh: list screens now show a Refresh control on web and refetch when the browser tab or window regains focus, so a newly published quiz appears without a hard reload.
